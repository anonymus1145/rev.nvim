1. Introduction                                       *rev-nvim-intro*

rev-nvim is an LLM-powered code review tool for Neovim. It allows you to
quickly get insights on your current git changes or specific blocks of code
delimited by debug breakpoints.

The plugin opens a vertical split with a live spinner while the LLM processes
your request, providing a markdown-formatted review.

==============================================================================
2. Requirements                                       *rev-nvim-requirements*

- Neovim >= 0.8.0
- `curl` installed in your system path.
- `git` (for full diff reviews).
- `nvim-dap` (optional, required only for |rev-nvim-breakpoint-review|).

==============================================================================
3. Configuration                                      *rev-nvim-config*

The plugin requires three environment variables to be set in your shell:

- `REVNVIM_API_KEY`: Your LLM provider API key.
- `REVNVIM_MODEL`:   The model name (e.g., "gpt-4o", "claude-3-5-sonnet").
- `REVNVIM_URL`:     The API endpoint URL.

Additionally, you must create a configuration file at:
`~/.config/nvim/REVNVIM.md` (or your OS equivalent stdpath).

This file should contain your system prompt or instructions for the LLM.
Example:
>
    # Do a code review
    Please look for logic errors, performance bottlenecks, and
    ensure the code follows clean coding principles.
<

4. Usage                                              *rev-nvim-usage*

The plugin provides two main entry points:

START REVIEW                                          *rev-nvim-start-review*
Run `:lua require('rev-nvim').start_review()`
This executes `git diff -W` on your current working directory and sends the
entirety of your unstaged changes to the LLM for a comprehensive review.

BREAKPOINT REVIEW                                  *rev-nvim-breakpoint-review*
Run `:lua require('rev-nvim').breakpoint_review()`
This allows you to review a specific range of code.
1. Open a file.
2. Set exactly TWO breakpoints (using nvim-dap) to define the start and end.
3. Trigger the function.
The code between those two lines will be sent for analysis.

==============================================================================
5. Keymaps                                            *rev-nvim-keymaps*

By default, the plugin suggests/sets the following mappings:

- `<leader>rv` : Start a full Git diff review.
- `<leader>rb` : Review the code block between two breakpoints.

To customize these, you can disable the default mappings in your init.lua and
map the functions manually:
>
    vim.keymap.set('n', '<your-key>', require('rev-nvim').start_review)
<
